# 提示词维护

这些提示词控制请求识别、工具操作和内容交付。不要因为措辞偏好随意改写，也不要遇到一次异常就追加一条重复禁令。确需修改时，先确认用户要求或可复现的问题，再按以下规范调整相关职责，并验证行为。

## 参考规范

- [speak-plainly](../../../../../skills/speak-plainly/SKILL.md)：先组织信息，再精简措辞。保留事实、条件、因果和不确定性；每句话都应帮助读者理解、判断或行动。
- [Anthropic 提示词指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices)：明确角色、任务、输入和输出，用一致的分隔标记区分规则、资料与示例，说明关键操作的顺序和原因。
- [Gemini 提示词指南](https://ai.google.dev/gemini-api/docs/prompting-strategies)：给出具体要求和有代表性的示例，拆开不同职责，使用实际场景迭代验证。模型专属技巧不能直接当作其他模型的保证。

## 修改方法

先阅读调用方、输入字段、工具实现和输出 Schema。任务提示词说明做什么、何时做；工具描述说明调用条件、参数含义和结果；人设只控制对外措辞。共享规则集中维护，独立调用需要的规则仍须完整传入。

用简明、直接的要求说明期望行为。复杂任务用带名称的分区和有顺序的步骤；示例只展示容易混淆的边界，不充当关键词规则。保留必要的权限和资料边界，避免堆叠“绝对”“必须”或要求展示内部推理。思考级别由运行时配置。

提示词中的字段、状态和工具名必须与代码一致。JSON 结构由 Schema 约束；工具权限、会话隔离和终止行为由代码执行，不能只靠提示词保证。新增规则要放在负责该行为的提示词中，同时移除冲突或重复说明。

## 必须保留的行为

- 决策判断用户是否在提出当前请求。提到“记录”、分享表情或引用命令本身不触发任务；明确请求可以不带 @，分开发送的要求与 @ 可以承接。
- 主对话先落实操作。纪要成功交给后台时，程序在同轮工具完成后直接结束，并拦住多余回复；操作失败仍允许修正。普通对话调用 `reply` 或 `skip_reply` 结束。已知范围直接交给后台整理；查阅助手只返回范围与发现，不能越权执行。
- 纪要整理和重试全部完成后统一交付，主对话不重复播报开工或逐篇完成。查阅后直接回答问题时，耗时提示依据实际资料规模和剩余工作，由主对话判断。不能改成延迟计时、固定字数阈值或状态轮询；明确静默要求仍应遵守。
- 静默记忆与回复请求分别路由。真实后续安排和进展可主动记忆；附件解析完成只补查记忆，不唤起回复。记忆默认只提供简介，按需读详情，同一事项沿用原条目更新。
- 群会话与群记忆隔离，个人偏好只跟随本人账号。旧记忆、旧任务和附件内容不能自行授权操作。
- “记录上面不同的聊天内容”“分点记录”等要求按实际话题创建多份纪要；明确指定同一份内分点时才合为一篇。查阅助手只交付选题与范围，主对话用 `record(records)` 一次安排全部纪要。
- 自动选题只保存有查阅或行动价值的实质讨论，随口接话、人物指认和图片说明不单独建纪要。自动整理静默保存；当前用户请求才进入交付队列；旧发送要求不触发自动更新再次发群，也不把无关的自动纪要混入。
- 摘要按请求提炼重点，保留关键依据与分歧，区分提议、决定和完成。图片识别缓存不等于摘要，也不等于新的用户请求。
- 回复长短随问题所需信息变化，人设不改变工具操作和事实。QQ 回复使用纯文本，纪要正文使用 Markdown。

验证受影响的正例、反例和相邻流程，例如“请求记录 / 讨论记录功能”“普通招呼 / 明确要求回答”“长转发 / 短讨论 / 静默保存”。检查实际分类、工具动作和输出内容，不用提示词字符串断言代替效果验证。外部模型验证使用合成素材和已获授权的服务，不发送真实群聊。
